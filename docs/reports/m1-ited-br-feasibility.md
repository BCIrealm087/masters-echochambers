# ITED-Br feasibility and the prior hashtag-graph baseline

**M1 · Step 2 · 2026-11-24**

Which of the thesis questions can ITED-Br support, and which inputs would have to be recovered? The public release preserves enough identifiers to attempt a graph of observed reposts, subject to testing how many referenced posts can be linked to authors. The original collection documentation describes additional fields for text, source URLs, timestamps and hashtags. Access to those fields in an approved extract is still unverified. The prior study’s graph and stance code is public. Its seed labels and exact run inputs still need to be recovered. [ITED-Br release README](https://github.com/Interfaces-UFSCAR/ITED-Br/blob/deae9a6ca931882ab736c2119e600af28f5d89cb/README.md) · [Original collection code and schema](https://github.com/Interfaces-UFSCAR/Codigo-Coleta-PLOS-ONE/blob/3cf054fe30016ffe767efc4655a4a4727038aeb8/README.md) · [Prior study code README](https://github.com/Interfaces-UFSCAR/Code-Hashtags-IEEE/blob/c39f1743d9e72cfb156e67d086a93c9cb2c034d0/README.md)

## What was verified

The evidence consists of the 2025 collection paper, the collection and prior-study code repositories, the prior manuscript, and a metadata check on the public release at the pinned revision above. The check listed Git directories for October 2022 and inspected Parquet schemas for seven files from October 16. It used file metadata to identify columns. The study has yet to measure how often references resolve, how much content can be recovered, or how well any graph represents the observed activity. [Collection paper](https://doi.org/10.1371/journal.pone.0316626) · [Prior-study note](../prior-study.md)

| Field or relationship | Public release evidence | Original collection documentation and implications |
| --- | --- | --- |
| Posts and authors | A sample of ordinary query posts, repost-query posts, and profile reply posts has `id` and `author_id`. The sampled user file has `account_id`. | The original schema also records account metadata. Followers and following counts are aggregate fields. Recovering actor accounts from the public samples depends on usable matches from the interaction IDs to post records. These profile queries target activity around candidate posts. |
| Time | The release has query and day partitions. The sampled post schemas have no explicit `created_at` field. | The original post schema documents `created_at`. Day partitions are suitable for locating inputs. Establish event time and timezone before comparing time windows or ordering events within a day. |
| Text, hashtags, URLs and media | The sampled post schemas have no text, hashtag or URL fields. | The original schema documents `text`, `hashtags`, `urls`, mentions and media relationships. ## Coverage and the comparison window

- The prior manuscript used **3 October inclusive to 31 October exclusive**, and the public code names four collection contexts for the graph. The public repository lists day folders for all 28 dates in `query_lula`, `query_bolsonaro`, `retweets_query_lula` and `retweets_query_bolsonaro`. This verifies partition presence. It leaves event completeness, date semantics and target-author coverage to a pilot. The prior window is a useful candidate for continuity. [Prior study methods](../prior-study.md) · [October Lula query](https://github.com/Interfaces-UFSCAR/ITED-Br/tree/deae9a6ca931882ab736c2119e600af28f5d89cb/data/query_lula/2022/10) · [October Bolsonaro reposts](https://github.com/Interfaces-UFSCAR/ITED-Br/tree/deae9a6ca931882ab736c2119e600af28f5d89cb/data/retweets_query_bolsonaro/2022/10)
- The collection used Portuguese-language queries with different terms and purposes. The collection paper reports a change to Bolsonaro’s search terms on October 4, within the prior window. Profile-based reply and quote collections are candidate-centered, and October folders for both candidate-number repost contexts run October 2–27. Any comparison that adds those contexts needs to account for the narrower overlap. Query labels identify how a record was retrieved. Stance must be estimated separately. [Collection paper, period and phases of collection](https://doi.org/10.1371/journal.pone.0316626) · [Lula number reposts](https://github.com/Interfaces-UFSCAR/ITED-Br/tree/deae9a6ca931882ab736c2119e600af28f5d89cb/data/retweets_numero_lula/2022/10) · [Bolsonaro number reposts](https://github.com/Interfaces-UFSCAR/ITED-Br/tree/deae9a6ca931882ab736c2119e600af28f5d89cb/data/retweets_numero_bolsonaro/2022/10)
- The collection paper reports publication dates from July 2022 to February 2023, while the public README gives a 2023–24 collection-date range. The October folder check establishes where the prior window can be found. For a later extract, retain the source revision and verify how its partition dates, event dates and reference-only records relate. The paper describes fetching referenced posts, which can bring in targets older than the interaction’s collection day or analysis window. [Collection paper](https://doi.org/10.1371/journal.pone.0316626) · [Release README](https://github.com/Interfaces-UFSCAR/ITED-Br/blob/deae9a6ca931882ab736c2119e600af28f5d89cb/README.md)

## What can be recovered from the earlier study

| Component | What is recoverable | Open question for reproduction |
| --- | --- | --- |
| Graph construction | The public script reads hydrated hashtag records, removes duplicate post IDs, normalizes hashtags, accepts exclusions from the label workbooks, constructs a weighted sparse co-occurrence graph and keeps its largest connected component. | Exact file manifest, the retweet files ending in or containing the expected `_fixed` marker, variant normalization or filtering beyond this code, and the original run revision. The published entry point has literal day placeholders and two calls to `list.append` with two arguments, so the checked-in command needs repair before a rerun. |
| Seed selection and propagation | The public code expects two pre-labeled XLSX inputs and uses GraphLearning’s Laplace model on the supplied labels. It maps candidate labels to pro, anti and, when present, undefined for each model. The public tree contains the scripts and README. No label workbook or seed-sampling utility appeared in that revision. | §3.2 of the manuscript describes the 500 most frequent hashtags per candidate and reports 409 and 404 consensus labels. §3.4 calls the selection random. The code loads a finished workbook, so it cannot resolve the discrepancy. The recorded label counts and model can guide a replication attempt once the workbooks or equivalent provenance are available. |
| Account stance scores | The public scoring entry point lists the ordinary candidate query paths. The scoring code applies the post threshold and drops unrecognized hashtags before the denominator is computed. | Confirm the actual run’s treatment of reposts, duplicated observations and the score denominator before comparing an account-level result to the manuscript. Distinguish the graph’s intended input contexts from the scoring step. |

The sources were inspected statically. Keep the prior algorithm as a specification-level baseline until an executable historical run can be reconstructed. If original seeds remain unavailable, a new labeled benchmark can compare algorithms on a common test set, with the resulting comparison scoped to that benchmark. ## Feasibility against the Step 1 questions

| Question | Minimum evidence | Current disposition and smallest later check |
| --- | --- | --- |
| Q1 · Candidate echo chambers and observed circulation | Source post and actor IDs, target references and a route to target authors, with an interaction type and a time window. | **Public structural starting point.** On a short, pinned slice, test the repost-to-target-author join. Count unique action IDs, target matches and unresolved targets by day and query context. Retain each action’s source memberships when deduplicating across contexts. Record whether a target originates outside the slice. Measure whether missing author joins concentrate by sharer, referenced post, or known group. Preserve typed references with known post IDs for repertoire analysis whenever the sharer's group is available. Report author-flow eligibility and post-overlap eligibility separately. Verify action dates before temporal testing and audit direct quote/reply targets separately. [Report 3 eligibility rules](reflexive-report-3.md#1-which-repost-events-can-enter-each-analysis) |
| Q2 · Graph construction and stance | Hashtag-bearing posts, candidate-specific seed labels, implementation settings and held-out evidence. | **Algorithm documented, exact rerun pending inputs.** Inventory the corresponding hydrated columns, label workbooks, removal rules and known run revision. A documented extract and newly sampled labels can support a type-level reconstruction. Inventory attributable Portuguese text and parent context separately for contextual validation, and authored histories for the account subset. Report missingness across candidate and week. [Report 4 reference design](reflexive-report-4.md#how-would-the-benchmark-be-judged) |
| Q3 · Political discourse and tactics | Brazilian Portuguese text, contextual posts for replies and quotes when needed, group membership and a documented coding unit. Verification of factual claims additionally needs external evidence. | **Conditional on text access and context.** Use an approved extract or a verified retrieval route. Check the availability of text and referenced context across groups and interaction types before comparing category frequencies. |
| Q4 · Verifiable LLM explanations | Evidence records for each claim, such as aggregates for structural claims or permitted excerpts for discourse claims, and a comparison using the same evidence. | **Structural explanations are possible in principle once Q1 yields validated aggregates.** Add discourse claims only where the evidence for Q3 is available. Test whether every generated claim points to a supporting record. |
| Q5 · Expert validation | Reviewable examples, group evidence, explicit criteria and independent judgments for claims that require them. | **Protocol design can proceed.** Select examples that become available through Q1–Q4. Record which conclusions depend on context an automated check cannot establish. Expert review belongs to the later validation milestone. |

## Handoff to Step 3

Carry forward the public repost structure as a candidate for a bounded pilot. Search for operational definitions and validation approaches that work with incomplete, query-selected interaction graphs. A repost edge can connect a sharing account to the author of the referenced post after a successful join. That records an observed action. Exposure pathways, private beliefs and the intermediary who first showed a post to the sharer would require additional evidence. Keep the choice of graph, window and validation threshold open until the literature comparison. [Step 1 protocol](m1-review-protocol.md) · [M1 roadmap](m1-research-directions.md)
