# Comparing graph construction and label propagation

**M1 · Step 4 · 2026-11-24**

Does the choice of graph or propagation rule improve candidate-relative stance estimates, and which graph choices make account communities more stable? For stance, the first comparison should cross **raw versus fractional hashtag co-occurrence** with **Gaussian Fields and Harmonic Functions (GFHF), Local and Global Consistency (LGC) and Poisson learning**, using the [Report 4 reference and text controls](reflexive-report-4.md). For account communities, compare directed modularity and Infomap on the same resolved repost graph, then test how much repeated sharing between the same accounts affects the partition. The two analyses have different outcomes. The stance track predicts a label for a hashtag relative to a candidate. The account track discovers groups whose future sharing can be tested. ## Hashtag stance

### Graphs to compare

Use separate Lula and Bolsonaro graphs. For comparability with the prior study, the initial candidate window is 3 October inclusive to 31 October exclusive, 2022, with the ordinary and repost query contexts for each candidate. Confirm how a repost gets its hashtag fields and which event date counts, then freeze those rules. Keep date, source memberships, normalization and the deduplicated post IDs fixed across graph variants. The benchmark node is a normalized hashtag–candidate pair. The two graphs can share a tag string while carrying different labels for it. The prior October graphs had 6,252 and 3,728 vertices and 163,474 and 156,654 edges. Those counts indicate the scale of the published outputs. The rebuilt graph sizes will depend on the slice and filtering rules. [Prior study](../prior-study.md) · [ITED-Br feasibility](m1-ited-br-feasibility.md)

| Graph | Nodes, edge and weight | What the comparison tests |
| --- | --- | --- |
| **Raw co-occurrence** | One node per normalized tag in a candidate graph. Each deduplicated post containing two distinct retained tags contributes 1 to their undirected edge. Use one incidence per normalized tag per post and omit self-loops. | A transparent reconstruction of the stated co-occurrence rule. A post with many tags contributes many pairs. |
| **Fractional co-occurrence (per tag)** | Same nodes, edges and posts. A post with k distinct retained tags contributes 1/(k−1) to each pair when k is at least 2. | Reduces the influence of tag-heavy posts. Each tag receives a total incident edge contribution of 1 from that post. A genuine pattern mainly expressed in tag-rich posts may also lose weight. |
| **Equal-post fractional sensitivity** | Each of the k(k−1)/2 pairs receives 2/[k(k−1)], giving each eligible post total weight 1. | Tests the review’s constant-post contribution alongside M1’s constant contribution per individual tag. |
| **Post–hashtag incidence graph, reserve** | Two types of nodes, unique posts and normalized tags. An undirected edge of weight 1 records that a post contains a tag. | Preserves the post as evidence and avoids building a clique in the input for every tag-heavy post. The graph has far more vertices and changes how paths are interpreted, so it is a follow-up if projection dominates cost or sensitivity. |

The raw and fractional projections change only weights. A three-tag post contributes 1 per pair in the raw graph and 0.5 in the fractional graph. Neither rule downweights a slogan that appears across many different repost events. Keep the per-event policy fixed for the first comparison and, if concentration warrants it, separately compare contribution capped by original post or author. The fractional rule adapts Newman's affiliation projection. Research comparing projections motivates the test. Neither source establishes which scheme works best for candidate-relative hashtags. [Newman, 2001](https://doi.org/10.1103/PhysRevE.64.016132) · [Cann et al., 2020](https://doi.org/10.1017/nws.2020.11)

### Propagation and controls

| Method | Rationale | Main caveat |
| --- | --- | --- |
| **Most frequent training label** | A graph-free baseline using the label counts among training seeds for that candidate. Report performance on the full test set. | Its label prevalence reflects the selected seeds. |
| **One-hop weighted vote** | Sum the edge weights to labeled neighbors by class. This tests whether propagation beyond directly labeled neighbors adds value. Record a tie or no labeled neighbor as an abstention. | Coverage depends on how seeds are distributed. |
| **GFHF / Laplace learning** | Keep the training labels fixed and extend their class scores harmonically to unlabeled vertices. This is the method family used in the prior work. | A component without a seed has no label constraint. Count it as uncovered. A densely connected region can mix discordant stances. |
| **LGC / soft label spreading** | Alternate spreading with a return to initial label scores using a symmetrically normalized adjacency. Tune the spreading weight on development labels. | Damping can change sensitivity to a seed. Incorrect seed evidence and systematic label bias still need separate checks. |
| **Poisson learning** | Replace fixed boundary values with seed sources and sinks. Test sparse supervision on each weighting and compare scores as seed budgets fall. | Its published low-label results motivate this comparison. Transfer to political co-occurrence graphs is an empirical question. |

For the primary comparison run GFHF, LGC and Poisson on raw and per-tag fractional weights. Include one-hop and nearest-seed controls on matched graphs and run the majority baseline once for each seed split. Use equal-post weights as a sensitivity. Assess TF-IDF and a Portuguese encoder on matched prediction units, with the independently annotated reference and leakage controls specified in [Report 4](reflexive-report-4.md#how-would-the-benchmark-be-judged). Keep the same node set, eligible labels and repeated splits. Let development data select LGC's spreading weight from a small range. Fit the graph methods with the same seed budget and keep the test labels hidden until scoring. Pass the frozen adjacency to the solvers. Building a new feature graph inside an implementation would invalidate the controlled comparison. [Zhu et al., 2003](https://cdn.aaai.org/ICML/2003/ICML03-118.pdf) · [Zhou et al., NeurIPS](https://proceedings.neurips.cc/paper/2003/hash/87682805257e619d49b8e0dfdc14affa-Abstract.html) · [Calder et al., 2020](https://proceedings.mlr.press/v119/calder20a.html)

The published prior-study script calls GraphLearning's `laplace` on its saved matrix. Current package documentation specifies an unregularized combinatorial Laplacian by default. Pin the version and record the effective settings for the new benchmark. The earlier run's package version, removal rules, seed workbooks and exact corpus inputs remain unverified. Use the documented method as the baseline and describe its results as a comparison on the reconstructed benchmark. Keep the recovery of the original run separate. ### Evaluate frequency bias and uncertainty

1. **Define the eligible label pool.** Use documented historical or newly acquired labels for training and development. Draw a separate stratified final reference, reserved from seed selection, tuning, calibration and graph design. Apply one codebook for support, opposition and the prior undefined category across methods. Retain disagreement or ambiguity in the reference record, distinct from a model abstention. Group spelling variants and near-duplicate slogans within each candidate before splitting, so one variant cannot seed another across a split. Freeze any eligibility rule learned from annotations on development cases. Keep information about the same tag's stance toward the other candidate out of training for this comparison.
2. **Compare equal seed budgets.** Vary frequent-first, uniform, frequency-stratified, degree-stratified and graph-coverage training sets on the same untouched reference, keeping budgets and, where feasible, class counts comparable. Choose labels only from the training pool. Use multiple recorded splits, with the same partitions for all methods. If every recoverable label comes from high-frequency tags, report what can be learned in that range. Assessing the tail requires reference labels for the tail. The earlier workbooks and independent expert judgments are potential inputs for a later milestone. [Step 2 feasibility](m1-ited-br-feasibility.md) · [Shchur et al., 2018, preprint](https://arxiv.org/abs/1811.05868)
3. **Make coverage visible.** Test label prediction transductively first. Test vertices and their unlabeled edges can appear in the graph. Track all eligible held-out keys, including isolates, filtered nodes, missing nodes and components without seeds. Report pooled and per-candidate macro F1 with abstentions counted as misses for their true class, per-class precision and recall, and coverage by frequency band. Report accuracy conditional on prediction alongside coverage and compare methods on shared covered cases as a diagnostic. Summarize paired differences across splits and the spread across splits. Use labels from an independently defined later slice for a separate transfer check where possible. Freeze the original score mapping and report when a later tag is unseen.
4. **Explain errors.** Review cases whose predictions change when the graph weighting changes and cases whose predictions change on a fixed graph when the algorithm changes. Report nearby labeled tags and their edge weights as diagnostics. High-impact confusions include irony, opposing uses of the same slogan and politician names invoked in unrelated contexts. Brazilian Portuguese tweet-level stance resources supply useful annotation and transfer designs. Their labels are at a different unit from candidate-relative hashtags in this benchmark. [UstanceBR](https://doi.org/10.1007/s10579-025-09896-3) · [Christhie et al., 2018](https://homepages.dcc.ufmg.br/~fabricio/download/brasnam2018.pdf)

## Cost and decision criteria

- **Hashtags.** Count eligible posts, distinct tags per post, pair emissions, unique pairs, components and seed coverage. A post with k distinct tags emits k(k−1)/2 pairs in either projection. Fractional weighting changes weights while retaining the same potential sparsity pattern. An aggregated sparse adjacency and iterative or sparse solvers are suitable first choices. Measure wall time, peak memory and solver convergence rather than assuming the cost from the published graph size.
- **Accounts.** Measure event and join costs separately from partitioning. Keep the working graph sparse and retain the event ledger with provenance for the holdout and sensitivity checks. Benchmark graph construction, clustering, repeat runs and null sampling on the same bounded slice. Report CPU, peak memory and an explicit time budget before expanding the window.
- **Decisions.** Carry a stance alternative forward if it consistently improves held-out performance at comparable coverage, or extends coverage without an unacceptable error increase. Keep a simpler method when the new method's measured advantage does not justify its added cost. For account communities, prefer reproducible partitions that lead to interpretable, stable validation results. A simpler graph that exposes sensitivity to a few accounts is informative even if its groups differ.
